# UNL City Hub — Surgery Report 2026-07-21

Four parallel audits (core runtime, data layer, worker/security, structure) followed by a fix phase. Every finding was verified against the actual code before being touched; nothing was reported or fixed on speculation. `tsc -b` clean, `vite build` clean, worker `wrangler deploy --dry-run` build clean.

## CRITICAL — fixed

| # | Finding | Fix |
|---|---------|-----|
| C1 | **App crash on city switch away from Bangkok** — `removeSource('src-districts')` threw while `ly-districts-highlight` (and `ly-osm-emergency-label`) still used the source; default path, first Bangkok→other-city switch hit the root ErrorBoundary | Added missing layer IDs to the teardown map + per-entry try/catch so cleanup always completes (`use-bangkok-layers.ts:70-90,261,290`) |
| C2 | **Forecast "next 24h" misaligned by each city's UTC offset** — Open-Meteo returned city-local hour strings, code matched them against UTC "now"; current AQI, peak hour, and cross-city lag correlations were all shifted (Bangkok: 7h stale) | Both forecast fetchers now request `timezone=UTC`; peak-hour rendering parses UTC explicitly and labels in city tz (`openmeteo-forecast.ts`); same browser-local parse fixed in consumers `ForecastPanel.tsx:66-88`, `predict-prepare.ts:56` |
| C3 | **Air4Thai parser matched zero real fields** — read `s.lng`/`s.PM25`/`s.AQI` while the live API sends `lat`/`long`/`AQILast.*`; every station dropped, layer dead while looking healthy; `http://` base mixed-content-blocked | Parser rewritten for the verified live shape, `-1` sentinels handled, `https://` base (`air4thai.ts`) |
| C4 | **GISTDA fires showed 1,001 hotspots from April 2023 as "24h fires"** — `recent.length ? recent : all` fallback silently substituted a frozen upstream layer | Returns the honest (possibly empty) recent set + `stale`/`latestDate` markers (`gistda.ts`) |

## HIGH — fixed

- **Popup listeners stacked on every basemap switch** (N clicks → N popups): wiring now persists across `setStyle` without re-registering (`use-bangkok-layers.ts:176-180`)
- **In-flight layer loads resurrected Bangkok layers after city switch / ignored toggle-off**: `.then` now bails on torn-down mode and reads live active-ids (`:65-70,138-144`)
- **City switch during style swap silently dropped** — `map.once('load')` never refires; switched to `style.load` (`MapView.tsx:403`)
- **Error-as-data caching defeated stale-while-error** — 11 fetchers (waqi, gdelt, nasa, tmd, alphaearth, gdacs, asean-aqi, datagov-sg, city-reporter, tomtom, rainviewer) now **throw** on failure so `cachedFetch` serves real stale data instead of caching confident empties
- **Fabricated fallbacks fed the correlation engine** — thaiwater's frozen `2026-05-26` readings and airbnb's 15 dummy listings now carry `isFallback` and are excluded from insights; airbnb URL moved to `https://`
- **Holt-Winters NaN** when `period ≤ n < 2·period` (24-point district calls) — guarded with flat-line fallback; worker forecast POST got a 20s timeout
- **Worker: CORS regression from the hardening commit** — `json()` hardcoded `hub.nonarkara.org`, browser-blocking `/forecast`, `/narrate`, `/ee/mapid` on pages.dev/previews; per-request CORS now threaded through all 15 call sites
- **Worker: spoofable Referer gate + zero rate limiting on AI-cost routes** — added per-IP fixed-window limiter (20 req/min, best-effort per-isolate, documented) + cost bounds (narrate context ≤ 8 KB, forecast series ≤ 500 points)

## MEDIUM / LOW — fixed

- `buildings-3d` camera tilt now only fires when the layer actually exists
- `applyInsight` stale-timeout flight back to the previous city — timeouts tracked/cleared, city read at fire time
- `?` shortcut could open Settings but never close it (stale closure) — deps fixed
- Timeline scrubber off-by-one-day in UTC+ zones — now pure UTC, consistent with SplitCompare
- Reloaded compare sets (≥2 pinned) couldn't be viewed/exited — `compareMode` derived on rehydrate
- One failed lazy chunk killed the whole dashboard — per-panel ErrorBoundaries
- SplitCompare: failed fetch no longer wipes good snapshots; loading indicator doesn't flash on cache hits; p-value hidden when n < 10
- Cache-key collisions: gdelt `max`, glofas `days`; redundant WAQI double-cache removed
- flood-forecast `-Infinity` peak when all discharges null → nullable peaks
- Unguarded `AbortSignal.timeout` (Safari <16 crash) → shared `timeoutSignal()` everywhere; 15s timeouts added to ~20 previously unbounded fetches
- Spearman ties get average ranks; historical-AQI window aligned to UTC; city-generator area × cos(lat); NDVI dates snap to the 8-day GIBS cadence; og:image canonicalized to hub.nonarkara.org; worker error responses no longer leak internals

## Structural surgery

- **Deleted dead chain:** `supabase-cache.ts` + `lib/supabase.ts` (zero importers; RLS silently rejected all writes anyway) + `@supabase/supabase-js` dependency removed
- **Deleted 2.8 MB** `src/data/slic-rankings.json` (superseded by the compact slic-cityhub snapshot)
- Removed dead `loadBangkokDistricts` export; stale `todo.md` entries corrected
- **Service worker:** HTML is now network-first (cache fallback) — stale-shell "Failed to fetch dynamically imported module" can't strand returning users; `vite:preloadError` self-heal reload added in `main.tsx`
- **Performance:** Firebase SDK (~154 KB gzip) was eagerly loaded at startup for one analytics call — `firebase.ts`/`db.ts`/`gemini.ts` rewritten fully lazy; it now loads on first chat/action/analytics use. Verified: `dist/index.html` no longer preloads the firebase chunk. Critical path = index (173 KB gz) + react + maplibre (the map is the product — stays eager)

## Honestly not verified

- **No visual/browser verification was performed** — typecheck + build + worker dry-run only. Rendering (especially ForecastPanel ticks, Bangkok layer teardown, SplitCompare panes) should be eyeballed on the live site.
- MapLibre `removeSource` throw behavior assumed from documented semantics, not executed.
- Cloudflare dashboard state (rate-limit rules), Firebase console (App Check, Firestore rules for `actions` — likely open writes), Supabase live RLS, provider-side key restrictions: all outside the repo, unverifiable from here.
- **Not deployed.** Deploy is manual: `npm run build` → `wrangler pages deploy dist --project-name=city-hub --branch=main`, plus `wrangler deploy` in `worker/` for the worker changes.

## Remaining known gaps (not bugs)

- Firebase AI Logic + Firestore have no App Check; Firestore `actions` rules are probably public-write — add App Check + rules.
- TomTom/Longdo keys ship in the bundle by design — restrict them provider-side.
- Worker rate limiter is per-isolate; a KV/Durable Object or CF Rate Limiting rule makes it a hard quota.
- The traffic→PM2.5 "correlation" in `correlations.ts:31` is mathematically vacuous (no timestamps) — feature work, not a crash; left as-is with this note.
