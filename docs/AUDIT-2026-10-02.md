# City Hub System Audit — 2026-10-02

Scope: brand/PWA integration, responsive map UI, Bangkok and Slovenia digital-twin paths, source honesty, dependency health, and production rendering.

## Verified fixes

- Extracted five transparent City Hub brand variants and six launcher assets from the supplied flattened PNG. The extraction is reproducible with `scripts/extract-city-hub-brand.py`.
- Added installable-web-app metadata and a truthful Android/iPhone install surface. It does not imply App Store or Play Store distribution.
- Moved the fixed About dialog outside the filtered top bar; its desktop bounds now stay inside a 1280×720 viewport. Added Escape-to-close, dialog semantics, a visible 44×44 close control, and phone layout rules.
- Phone QA at 390×844 has no horizontal document overflow. The city introduction now starts docked as a compact strip on small screens instead of covering the map.
- Upgraded MapLibre GL JS to 6.11.2 and configured the bundled Vite worker. Bangkok 3D buildings and imagery render in dev and production preview.
- Upgraded Firebase to 12.19.0 and websocket-driver to 0.7.5, removing the critical advisories present before the audit.
- Corrected Bangkok population boundaries to official NSO/BORA 2024 figures: BMA registered population 5,455,020 (3,477/km²); Bangkok and five surrounding provinces 10,906,861 (1,405/km²). The former 6.2M “shadow population” claim incorrectly subtracted different geographies and was removed.
- Corrected TRUE Digital Park to Punnawithi, Bangkok, and removed unsupported governance superlatives.
- Thaiwater and Inside Airbnb now fail closed. Fabricated fixtures cannot enter maps, vitals, or correlations. Thaiwater layers remain visible in the catalog but disabled until a stable station endpoint is verified.
- Renamed simulated train telemetry and dated Airbnb data so neither appears real-time. Source catalogs now say `IN APP`, not `LIVE`, unless runtime health is actually known.
- Replaced whole-panel `LIVE` stamps on the Bangkok and Kranj twins with `LOCAL TIME`; live badges remain only on actual iTIC and GloFAS feeds.
- Corrected the About privacy statement to disclose optional Firebase usage events when configured.

## Remaining risks

| Severity | Item | Current behavior / next step |
|---|---|---|
| High (audit tool) | Four npm advisories are reported through `@firebase/firestore` → `@grpc/grpc-js` 1.9.16. | The vulnerable gRPC server behavior is not used in this browser client. Firebase 12.19 still pins the old range; do not force npm's suggested downgrade to Firebase 9.14. Recheck on the next Firebase release. |
| Medium | TMD and Air4Thai direct requests fail in local production preview. | The UI shows no data rather than invented data. Verify the configured Cloudflare proxy in deployment. |
| Medium | Several comparison/economic figures remain curated static indicators with mixed reference years and boundaries. | Keep year/source labels visible. A follow-up should move every comparison metric into a typed provenance registry with geography, reference period, unit, and retrieval date. |
| Low | MapLibre logs glyph-PBF compatibility warnings and renders affected labels locally. | Visual labels render; replace the legacy glyph endpoint or self-host a MapLibre-compatible font stack to remove noise. |
| Info | Main, Firebase, and MapLibre chunks exceed Vite's 500 kB warning threshold. | Firebase is lazy loaded. Further route-level splitting can reduce cold-start transfer. |
