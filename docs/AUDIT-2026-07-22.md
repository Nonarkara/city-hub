# UNL City Hub — Pre-Ship Audit (2026-07-22)

Scope: technical ship-blockers + runtime correctness across `src/` (143 files), `worker/`, build & env hygiene. Method: two parallel read-only sweeps (65 components/hooks/stores; 44 data/lib modules) + manual reads of `worker/src/index.ts`, `App.tsx`, `cached-fetch.ts`; every finding below was re-verified against the exact code before being reported, and key external claims were tested live.

**Git state:** clean `main`, no unmerged branches or stranded worktrees. `tsc -b` and `vite build` were green before and after the audit.

---

## Findings & fixes applied

### HIGH

**H1 · FIRMS fire data was completely dead — the SMOKE feature and `fires-firms` layer could never render** ✅ FIXED
- `src/data/nasa.ts:21` called `…/api/country/csv/c/VIIRS_SNPP_NRT/THA/1` with the literal `c` in the MAP_KEY position. Live test: `HTTP 400 Invalid API call`. The endpoint is also CORS-blocked from the browser.
- Blast radius: `use-bangkok-layers.ts:757` (fires layer) and `SmokeConeOverlay.tsx:77` — the overlay early-returns without FIRMS data, so the topbar SMOKE button was permanently inert.
- Fix: `nasa.ts` now routes through the Worker proxy (`${VITE_PROXY_URL}/firms/…`) in production, or uses `VITE_FIRMS_MAP_KEY` directly in dev; it throws honestly when neither is configured. Worker (`worker/src/index.ts`) injects a new `FIRMS_MAP_KEY` secret into the URL path after `/csv/`. `.env.example` documents the free key registration.
- **Action required to go live:** register a free FIRMS MAP_KEY and set it as a Worker secret: `cd worker && npx wrangler secret put FIRMS_MAP_KEY`, then redeploy the worker.

**H2 · Smoke-cone map layers leaked on every effect run** ✅ FIXED (latent — was unreachable due to H1, would have compounded the moment FIRMS worked)
- `SmokeConeOverlay.tsx` added cones as `smoke-cone-${hours}-${lat}` (line 131) but both cleanup paths removed unsuffixed `smoke-cone-${hours}` IDs that never existed — 15 sources+layers per run, never removed, stale cones persisting across city switches.
- Fix: cone IDs are now tracked in a ref; both cleanup paths remove exactly what was added.

**H3 · Production builds silently fell back to the dev Firebase project** ✅ FIXED
- `src/lib/firebase.ts:4-9` hardcoded the full dev config (incl. API key) as a fallback. A prod build missing `VITE_FIREBASE_*` would write SitRep drafts/analytics into `unl-city-hub-dev-1` with no error. (The key itself being in git is by-design for Firebase web keys — the defect was the silent cross-environment redirect.)
- Fix: fallback applies only in dev builds; in prod, missing env vars disable Firebase with a console warning — all callers already degrade gracefully (`db.ts` try/catch, `trackEvent` swallow, `ActionCenter` catch added below).

### MEDIUM

**M1 · Command palette executed stale closures** ✅ FIXED
- `CommandPalette.tsx:149` memo deps were `[activeLayers, districts, governorMode]` while closing over `globeView`, `forecastOpen`, `splitOpen`, `chatOpen`, `basemap`, `activeCity`, `allCities` — e.g. toggling globe via hotkey then opening the palette showed "ENTER GLOBE VIEW" and did nothing. Deps now complete.

**M2 · AlertCard "WHY?" froze forever on narrate failure** ✅ FIXED
- `AlertPanel.tsx:206-222` awaited `narrate()` with no try/catch — a rejection left the button stuck on "…" plus an unhandled rejection. Now try/catch/finally.

**M3 · 16 fetch call sites had no timeout — one stalled connection wedged panels and the inflight dedup** ✅ FIXED
- 13 files patched with the project's existing `timeoutSignal()` helper: airbnb (30s, large CSV), asean-aqi, alphaearth, city-reporter, datago-bma ×2, datago, flood-forecast, openaq, openmeteo-forecast ×3, openweathermap, rainviewer, tomtom-traffic ×2, bma ×2 (plus missing `res.ok` checks). nasa.ts also got a timeout as part of H1.

### LOW (fixed)

- **L1 · ActionCenter unhandled rejection** on failed Firestore writes (`ActionCenter.tsx:20-23`) — now caught; card stays for retry. ✅
- **L2 · AqiSparkline NaN path** on a flat 24h series (`ComparisonPanel.tsx:153`) — `hi - lo || 1` guard. ✅
- **L3 · Unguarded `geo.features` + uncaught `load()`** in `useFloodComplaintCorrelation.ts:80,124-125` — `Array.isArray` guard + `.catch` on initial and interval calls. ✅
- **L4 · `sessionStorage` without try/catch** in the `vite:preloadError` self-heal (`main.tsx:30-31`) — throws in Safari private mode; now degrades to always-reload. ✅

## What was verified vs not

- **Verified by reading code:** every finding above; zustand stores (no render-loop selectors); timer/listener cleanup across ~40 sites; browser-compat crashers (no lookbehind/`AbortSignal.timeout`/`crypto.randomUUID` in app code — the one `AbortSignal.timeout` use is in the Worker, where it's supported); no hardcoded secrets beyond the noted Firebase dev config and TMD demo creds; `.env.local` properly untracked.
- **Verified live:** FIRMS endpoint returns HTTP 400 (H1); production build green after all fixes; worker passes esbuild syntax check.
- **Not verified:** rendered UI after these changes (no screenshot pass was run — the fixes are logic-level, but a visual smoke pass on Bangkok mode is recommended); worker behavior end-to-end (needs `wrangler deploy` + the new secret); Firestore security rules (out of repo scope).
